# Windows developer setup (read-only frontend only)

Native Windows 10/11 + PowerShell workflow for **running the read-only WebUI
frontend** (`frontend.py`), editing the project, and starting a local server.

> **Scope: frontend only.** This is *not* Windows backend support. The backend
> pipeline (`backend.py`), file locking, and thumbnail/image ingestion rely on
> `fcntl`, `os.uname`, and the macOS `sips` binary, so they do **not** run on
> native Windows. Do not try to run the backend or configure Ollama here — see
> the "What is unsupported on Windows" section below.

## Prerequisites

| Requirement | Where | Notes |
|---|---|---|
| **Python 3.11** | via the [Windows Python launcher](https://www.python.org/downloads/windows/) | Installed from python.org, it registers the `py.exe` launcher on `PATH`. |
| **PowerShell** | preinstalled on Windows 10/11 | All commands below are PowerShell. |
| **Git** | [git-scm.com](https://git-scm.com/download/win) | For cloning the repo. |

No `pip install` is required for this workflow: `frontend.py` uses **only the
Python standard library**, so `requirements.txt` is **not** needed on Windows.
(Third-party dev/test tools such as `ruff` are a separate concern — see issue
#29 — and are not part of launching the frontend.)

## Step 1 — Get the code

```powershell
git clone https://github.com/beckandwhite/VisionKB.git
cd VisionKB
```

All commands below are run from the **repository root** (the directory that
contains `frontend.py` and `config.template.json`).

## Step 2 — Verify Python is available

```powershell
py -3.11 --version
```

Expected: `Python 3.11.x`. If this fails, install Python 3.11 from
python.org (choose **“Add Python to PATH”**) and reopen the terminal.

## Step 3 — Create a virtual environment

```powershell
py -3.11 -m venv .venv
```

This creates `.venv\` containing `Scripts\python.exe`. (The project's own
`.venv` on macOS is gitignored; creating your own here is fine and the same
`.venv` is the right place on Windows too.)

## Step 4 — Create the workspace config (only if missing)

A fresh checkout has **no** `.workspace\` artifacts. The frontend reads its
environment from `.workspace\config.json`. Create it **once**, copying the
template, and **without overwriting** an existing config:

```powershell
if (-not (Test-Path ".workspace\config.json")) {
    New-Item -ItemType Directory -Force -Path ".workspace" | Out-Null
    Copy-Item "config.template.json" ".workspace\config.json"
}
```

The copied template's macOS `source_dir` (iCloud path), `ollama_base`, and
model fields **do not need to be changed to launch the frontend**. The frontend
is read-only: on first run with an empty workspace it shows an empty UI. It does
**not** start Ollama, send images, or call `sips`.

## Step 5 — Launch the frontend

```powershell
.\.venv\Scripts\python.exe frontend.py --port 8000 --open
```

- `--open` launches the default browser automatically; omit it if you'd rather
  open the URL yourself.
- Then open <http://127.0.0.1:8000/> in a browser.
- If port 8000 is already in use, try another port, e.g. `--port 8001`.
- Stop the server with **Ctrl+C**.

Quick check that the API answers for the empty workspace:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/overview
```

Expected: a JSON object (empty/funneled stages), not an error.

## Why the UI is empty on a fresh checkout

No tracker, annotations, results, or thumbnails are checked into git — they live
under `.workspace/` and are regenerated by the backend pipeline. A fresh clone
therefore has nothing to display yet. **Populating data is out of scope for this
guide** and requires the backend pipeline (see below), which does not run on
native Windows.

## What is unsupported on Windows

The backend and image pipeline are **not** Windows-compatible because they depend
on:

- **`fcntl`** — POSIX-only file locking used by the pipeline (`.pipeline.lock`).
- **`os.uname`** — not available on Windows.
- **`sips`** — the macOS image binary used for HEIC→JPEG conversion and
   thumbnails.

Because of these, on native Windows you **cannot**: run the backend (`backend.py`,
the per-source `work*` runners), run image ingestion / generate thumbnails, or
populate the workspace. The frontend above is read-only and does none of that,
which is why it works.

**No Ollama setup is needed for the frontend workflow.** Ollama is only required
by the backend vision/embedding steps on a supported (macOS) machine.
